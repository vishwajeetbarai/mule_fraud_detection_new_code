# Bank Account Fraud Detection (NeurIPS 2022 Benchmark)

Gradient-boosted fraud detection (XGBoost and LightGBM) on the real
**Bank Account Fraud `BaseDataset.csv`**: 1,000,000 account-opening applications,
31 features, `fraud_bool` target (~1.1% fraud). No synthetic data is used.

## Setup

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Download `BaseDataset.csv` from
[Kaggle](https://www.kaggle.com/datasets/sgpjesus/bank-account-fraud-dataset-neurips-2022)
into `data/` (git-ignored, 213 MB). Or use `--data PATH` / env var `BASE_DATASET_PATH`.

## Run

```bash
python src/train.py                                        # full run (CV + SHAP, long on small machines)
python src/train.py --sample-frac 0.1 --skip-cv --skip-shap   # quick smoke test on 10% of the real rows
pytest tests                                               # sanity/leakage tests
```

## Method

| Step | Detail |
|---|---|
| Split | Temporal on `month`: train 0-4, validation 5 (early stopping and threshold), test 6-7 |
| Missing values | `-1` sentinels in 5 columns and negative `intended_balcon_amount` become NaN, plus `_missing` flags |
| Features | Velocity ratios, credit-limit-to-income, total address months, phone-valid count; one-hot with levels fixed on train only |
| Dropped | `device_fraud_count` (constant 0), `month` (split key only), target |
| Models | XGBoost and LightGBM with `scale_pos_weight` for the ~1% class imbalance |
| Threshold | Chosen on the validation month at 5% FPR, then applied unchanged to test |
| Metrics | ROC-AUC, PR-AUC, TPR@1%/5% FPR (benchmark convention), precision/recall/F1 |
| CV | Expanding-window temporal CV, test months 3-7 |
| Explainability | Gain importance and SHAP (LightGBM) |

## Repository layout

```
src/config.py        paths, schema, split months, hyper-parameters
src/data_loader.py   CSV loading, schema validation, temporal split
src/features.py      leakage-safe preprocessing / feature engineering
src/evaluation.py    metrics and plots
src/train.py         end-to-end entry point
tests/               sanity tests on a slice of the real data
outputs/             generated metrics, plots, SHAP (models/ is git-ignored)
```
